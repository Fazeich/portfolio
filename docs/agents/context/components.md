# Component Context

## Page (`src/pages`)

- **PortfolioPage** (`src/pages/Portfolio`): Route `/` — a 3D top-down town (react-three-fiber). A low-poly character walks freely in a room with multiple altar signs; approaching an altar shows a tooltip, pressing E plays a 4-second interaction animation (expanding light ring + point light, raised arms, white fade-out) and navigates to the altar's target route.
  - `lib/TownScene.tsx`: Composes the 3D scene — ground, walls, stones, gravel, floor lines, all `ALTARS`, player, follow camera, lights (ambient + directional with shadows).
  - `lib/constants.ts`: `AltarDef` interface + `ALTARS` data array (id, position, billboard text, tooltip label/keyHint, altar AABB half-sizes, target route). Currently snake (`/snake`) and letters (`/letters`) altars. Also room dimensions, speeds, interaction duration, etc.
  - `lib/Ground.tsx`: Near-infinite floor — a single large plane (2000×2000) in one flat color `#f2ebe5` with a plastic-like material (`MeshPhysicalMaterial`: low roughness + clearcoat). No texture.
  - `lib/Walls.tsx`: Boundary walls around the walkable room (60×40) — four boxes on the room edges (`#e2d9cd`, plastic material) that visually cap the floor. Player movement is clamped inside via `PLAYER_MARGIN`.
  - `lib/Stones.tsx`: Decorative rocks scattered in a band just beyond the walls (seeded pseudo-random layout, 48 low-poly icosahedrons, `#8a857e` stone material, cast/receive shadow).
  - `lib/Gravel.tsx`: Gravel inside the room — a single `InstancedMesh` pool (900 dodecahedron pebbles, `#a89f92`-family shades) with per-instance transform/color, seeded layout, clear radius around each altar.
  - `lib/FloorLines.tsx`: Decorative floor markings — a central square (5×5) where the player spawns, plus thin lines from each square side extending to the four map borders (`#a89f92`, thin boxes just above the floor).
  - `lib/AltarSign.tsx`: Data-driven interaction target — a three-tier stone altar (3 stacked boxes, `#6b655c`) topped with an extruded 3D billboard text (`altar.text`). Text is drei `Text3D` (bundled `helvetiker_bold.typeface.json` font in `src/lib/assets/fonts/`, dark metallic slate `#263449`), wrapped in `Billboard` + `Center` so it always faces the camera. Renders one sign per entry of `ALTARS`.
  - `lib/CharacterModel.tsx`: Loads the rigged `Rona` GLTF character (`assets/character/character.gltf` via `useGLTF`), deep-clones it with `SkeletonUtils.clone` (so the cloned skin uses the cloned bones), normalizes its scale/feet position, and drives a procedural walk cycle on the Biped bones (thighs, calves, upper-arms, forearms, plus pelvis, spine1, spine2, and head). Limb motion is applied via quaternion deltas around the character's sideways axis (computed in world space, so it stays natural in any facing). Features include: smooth stop/start blending via exponential lerp on walkPhase, slerp turning interpolation, vertical body bob, pelvis sway, spine counter-sway with forward tilt, head stabilization, shoulder shrug, permanent arm adduction toward the torso (rest + walk), forward-only knee bend (phase-shifted, no hyperextension when the leg trails behind), and a raised-palm elbow profile with constant base bend while walking. Movement is clamped to the room bounds and collides with every altar AABB (`resolveAltarCollision`, circle-vs-box push-out). Handles free movement, the raised-arms interaction pose, and the expanding interaction ring + point light. On interaction it stores the activated altar's target in `state.interactionTarget` and navigates there after the animation.
  - `lib/assets/character/`: GLTF character source files + textures (Rona, CC-BY-NC-4.0 — see `CREDITS.md`). `character.gltf` is generated by `scripts/embed-gltf.mjs`.
  - `lib/CameraRig.tsx`: Smooth top-down follow camera; finds the nearest altar within `INTERACTION_RADIUS`, projects it to screen space and fills the tooltip (label, key hint, target route).
  - `lib/state.ts`: Mutable game state ref (player position/facing/walkPhase/targetWalkPhase, interaction timer, `interactionTarget`, tooltip).
  - `lib/controls.ts`: Keyboard input (WASD/arrows for movement, E for interaction).
  - `ui/InteractionTooltip.tsx`: DOM overlay above the hovered altar — ref-driven via rAF (no React re-renders).
  - `ui/PortfolioPage.tsx`: Canvas + tooltip + white fade overlay + navigation callback.
- **LettersPage** (`src/pages/Letters`): Route `/letters` — Letter Rain. A full-screen 3D canvas; typing any printable character **anywhere on the page** spawns a single 3D letter above the top boundary. It falls and collides with the side/bottom bounds and with other letters (top stays open). The field is one row deep (`AREA_HALF_D` = 1.5 × letter depth) — letters are locked at z = 0 and pile into a single row. Letters never rotate around Y — they only tilt, and the tilt is **free and dynamic**: letters keep their landed angle, wobble on impact (no restore to a fixed flat pose). Each letter is at least 120×120 px on screen (recomputed from viewport/camera on resize). Cap: `MAX_LETTERS` (9) — the oldest letter is evicted when full.
  - `ui/LettersPage.tsx`: Full-screen layout. Mutable world in a ref; subscribes `letterTyped`/`clearLetters` Effector events and bumps a React counter so the letter list re-renders only on spawn/evict. A single window `keydown` handler (no input field): printable chars → `letterTyped`, Escape → back to the town.
  - `ui/LettersScene.tsx`: Composes the 3D scene — background color, ambient/directional/point lights, floor plane, translucent bounds walls (front/back at ± letter depth), `Letters`, the physics game loop, the camera rig, and Bloom. Camera fits the play box to the viewport each frame and writes `pxPerWorld`/`letterScale` into the world.
  - `ui/Letters.tsx`: One `<mesh>` per letter (drei-style `TextGeometry` from the shared font cache), memoized and keyed by id — old letters are never re-mounted/re-created when new ones spawn, only their transforms are synced from the world each frame. Uses a shared `MeshStandardMaterial` with a soft emissive for Bloom.
- **SnakePage** (`src/pages/Snake`): Route `/snake` — the 3D Snake game. Composes the 3D `<Canvas>` (Arena, Snake, Food, Shards, Effects, CameraRig, lights, Bloom) with DOM overlays (Hud, Screens).
  - `ui/GameLoop.tsx`: Orchestrates the game loop inside Canvas — resets the world when the store's `gameId` changes (new game only, not on resume), steps physics, dispatches score/HP/boost events.
  - `ui/PointerTracker.tsx`: Raycasts the mouse pointer onto the arena floor plane and writes the target point into `inputRef` for steering. Mouse steering is active **only while the left mouse button is held** and is **inverted** (the snake steers away from the cursor); releasing LMB stops steering (WASD keeps working).

## Feature Components (`src/components`)

- **Arena** (`src/components/Arena`): Renders the 3D arena — neon-grid floor (drei `Grid`) and 4 semi-transparent walls with glowing edges.
  - `lib/constants.ts`: Wall thickness.
- **Snake** (`src/components/Snake`): Renders the snake as an `InstancedMesh` pool (head + chain), synced from world state each frame. Per-segment colors (head→tail gradient) and orientation.
  - `lib/render.ts`: Per-frame matrix/color sync for the instanced chain. Unused instances (beyond the current segment count) are scaled to 0 every frame to keep them invisible.
- **Food** (`src/components/Food`): Renders "protected" food — translucent shell sphere with a glowing core. Pool of `MAX_FOODS` slots synced from world state.
- **Shards** (`src/components/Shards`): Renders shard pickups as a single `InstancedMesh` octahedron pool (1 draw call). Per-instance colors distinguish edible (amber, from theme) from inert just-broken (gray).
- **CameraRig** (`src/components/CameraRig`): Follow camera behind the head with smoothing, FOV kick on boost, orbit mode on the menu screen.
  - `lib/constants.ts`: Camera offsets, FOV values, orbit params.
- **Effects** (`src/components/Effects`): Ambient dust points + a particle burst pool triggered on shell breaks.
  - `lib/particles.ts`: CPU particle simulation (positions/colors/lifetimes, circle sprite texture).
  - `lib/constants.ts`: Particle counts, speed, lifetime.
- **Hud** (`src/components/Hud`): DOM overlay — score, best score, HP hearts, boost bar. The boost bar is ref-driven (updated in a `requestAnimationFrame` loop straight from the mutable world, no React re-renders) and exposed as `role="progressbar"`; hearts carry an `aria-label`. The boost bar dims and shows a `КД X.Xс` countdown while the boost cooldown is active.
  - `lib/styles.ts`: styled-components for the HUD.
- **Screens** (`src/components/Screens`): DOM overlays for `menu` / `paused` / `gameover` phases — title, rules, controls, play buttons, social links (react-social-icons). Handles Esc-pause and Space/Enter-start hotkeys. Dialogs use `role="dialog"` + `aria-modal` and a Tab focus trap (`useFocusTrap`).
  - `lib/styles.ts`: styled-components for screens/panels/buttons.
